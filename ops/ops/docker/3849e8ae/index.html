Docker 网络

一、为什么 Docker 需要网络

在 Docker 里，每个容器本质上是一个隔离的进程 + 独立网络命名空间：

  • 有自己的 IP
  • 有自己的网卡（veth）
  • 有自己的路由表

👉 所以问题来了：

  • 容器如何访问外网？
  • 容器之间如何通信？
  • 容器如何被宿主机 / 外部访问？

这些都由 Docker Network 解决。

二、Docker 的网络模型（核心概念）

​ Docker 使用的是 Linux Network Namespace + 虚拟网桥（Bridge）。

关键组件：

组件 作用
Network Namespace 容器的“网络隔离空间”
veth pair 容器 ↔ 宿主机的虚拟网卡对
bridge 二层交换机，连接多个容器
iptables NAT、端口映射、隔离规则

三、Docker 默认网络

安装 Docker 后，默认就有一个网络：

👉 bridge:

为每一个容器分配、设置IP等，并将容器连接到一个docker0的虚拟网桥，默认为该模式。

  1. 每个容器拥有：

    • 独立的 Network Namespace
    • 独立的虚拟网卡（eth0）
    • 独立的 IP

  2. 通过 veth pair 接入宿主机的 docker0 网桥

  3. 默认通过 iptables SNAT 访问外网

默认 bridge 网络 不提供基于容器名的 DNS 解析

👉 host

容器将不会虚拟出自己的网卡，而是使用宿主机的IP和端口.

  1. host下的容器
    • 没有 Network Namespace
    • 与宿主机 共享同一套网络栈
    • 容器进程监听的端口 = 宿主机端口
    • host 模式下 -p 端口映射参数 无效

👉 none

容器有独立的Network namespace 但并没有对其进行任何设置。

  1. none下：
    • 有 Network Namespace
    • 只有 lo 回环接口
    • 没有 IP、路由、DNS
    • 需要用户手动配置网络
  2. 常用于：
    • 安全测试
    • 自定义网络插件
    • 极端隔离场景

👉container

新容器：

  • 不创建自己的 Network Namespace
  • 直接加入目标容器的 Network Namespace

因此共享：

  • IP
  • 网卡
  • 端口
  • 路由
  • DNS

总结

Docker 的四种网络模式，本质区别在于 Network Namespace 是否独立或共享。

模式 Network Namespace IP 网卡 端口 常见用途
bridge 独立 独立 独立 隔离 默认业务容器
host 共享宿主机 宿主机 宿主机 宿主机 高性能/探测
none 独立 无 无 无 强隔离
container 共享其他容器 共享 共享 共享 sidecar

五、Docker-birdge

什么是birdge模式：

docker-bridge 是 Docker 在宿主机上创建的 Linux 虚拟网桥（docker0），用于把多个容器接入同一个二层网络。

Docker 会默认创建一个名字为docker0的网桥，它在内核上连通了其他物理或虚拟网卡。所以所有容器和本地主机都放到同一个物理网络。并分配一个网段：172.17.0.1/16

网桥模式docker0 ，类似一个交换机有一些接口，每个接口叫做veth，每个容器也有一个网卡接口是eth0，此时两个容器的网络也是互通的。

启动一个容器后，再次查看宿主机的ip addr，多了一组映射关系。内层的容器是相反的。

六、为什么不推荐直接用默认 bridge

问题 原因
不能用容器名通信 无内置 DNS
网络混乱 所有容器堆在一个网段
不利于隔离 无服务级网络边界
不利于编排 不可控

自定义 bridge

✅ 自动 DNS（容器名 = 域名）

✅ 网络隔离

✅ 可读性强

七、Docker host

Docker host 模式

host 模式下，容器不再拥有独立的 Network Namespace，而是直接复用宿主机的网络栈。

Docker 不会做以下事情：

  • ❌ 不创建 Network Namespace
  • ❌ 不创建 veth pair
  • ❌ 不创建 bridge
  • ❌ 不分配容器 IP
  • ❌ 不做端口映射

Docker 只做一件事：

把容器进程直接放进 宿主机的网络命名空间

✅ 优点

  1. 极致性能
  2. 网络行为可预测
  3. 无端口映射、无 NAT
  4. 网络排错简单（tcpdump、ss）

❌ 缺点（致命）

  1. 端口冲突
  2. 无网络隔离
  3. 安全性差
  4. 无法多实例部署同一服务

八、Docker none

none 模式：

none 模式下，容器拥有独立的 Network Namespace，但 Docker 不为其配置任何网络资源。

这是 Docker 提供的最“干净”的网络隔离形态。

Docker 的行为是：

✅ 会做的

  • 创建 Network Namespace
  • 创建容器进程
    • 保留 lo（回环接口）

允许你“从零构建网络”

none 模式是：

给你一个空白 Network Namespace

你可以手动：

  • 创建 veth
  • 分配 IP
  • 加路由
  • 接入自定义 bridge
  • 接入 SDN / CNI

九、Docker container

container 模式下，新容器不创建自己的 Network Namespace，而是直接加入另一个已存在容器的 Network Namespace。

此时：

  • app 和 busybox
  • IP 完全一致
  • 端口空间完全一致
  • 网卡、路由、iptables 完全一致

十、自定义网络

自定义网络

Docker 自定义网络本质是：Docker 托管的 Linux bridge + 独立子网 + 内置 DNS（127.0.0.11）。

默认 bridge 的“加强版、生产版”。

创建一个自定义网络

你会看到：

  • 网桥：br-xxxx
  • 子网：172.18.0.0/16
  • 网关：172.18.0.1

再创建网段会是19……

手动指定网段的方式

启动容器时指定网络

容器已经启动后，再接入网络

⚠️ none / container / host 不能动态切换
