1. Docker简介

什么是Docker

Docker是一个开源的平台，用于开发、部署和运行应用程序。它允许开发者将应用程序及其所有依赖项打包到一个标准化的单元中，称为容器。这些容器可以在任何支持Docker的环境中一致地运行，从而简化了软件的分发和部署过程。

Docker的核心概念

  1. 镜像（Image）：Docker镜像是一个只读的模板，其中包含了运行应用程序所需的所有内容，包括代码、运行时、库和配置文件。镜像是构建容器的基础。
  2. 容器（Container）：容器是镜像的一个运行实例。它是一个轻量级、独立的执行环境，可以在几乎任何地方运行。容器在启动时创建一个隔离的进程空间，确保应用程序之间不会相互干扰。
  3. Docker引擎（Docker Engine）：这是一个轻量级的运行时和工具集，用于构建和运行Docker容器。Docker引擎包含了守护进程（daemon），一个REST API以及一个命令行界面（CLI）。
  4. Docker Hub：这是一个云端的注册表服务，用于存储和分发Docker镜像。开发者可以从Docker Hub下载公共镜像，或者上传自己的镜像以供他人使用。

Docker的优势

  1. 便携性：容器包含了应用程序的所有依赖项，可以在任何支持Docker的环境中运行。这使得应用程序的迁移和部署变得非常简单。
  2. 一致性：使用Docker，开发、测试和生产环境可以完全一致，减少了“在我机器上能跑”的问题。
  3. 高效性：Docker容器启动速度快，资源开销小，允许在同一主机上运行更多的应用程序实例。
  4. 隔离性：容器运行在各自的进程空间中，确保了应用程序之间的相互隔离，提升了安全性。

2. Docker如何工作

Docker架构

Docker的架构由以下几个主要组件组成：

  1. Docker客户端（Docker Client）：这是用户与Docker进行交互的主要方式。用户可以通过命令行界面（CLI）向Docker守护进程（Docker Daemon）发送命令。
  2. Docker守护进程（Docker Daemon）：这个后台进程负责构建、运行和管理Docker容器。它接收来自Docker客户端的命令，并执行相应的操作。
  3. Docker镜像（Docker Images）：镜像是一个只读的模板，用于创建Docker容器。每个镜像包含运行应用程序所需的所有文件和配置。
  4. Docker容器（Docker Containers）：容器是镜像的一个运行实例。它是一个轻量级、独立的执行环境，包含了应用程序及其依赖项。
  5. Docker应用市场（Docker Registry）：这是一个存储和分发Docker镜像的服务。Docker Hub是最常用的应用市场，用户也可以搭建私有应用市场。

已启动一个redis为例。

  1. Docker Client 发送一个 docker pull redis 的命令到 Docker Daemon，然后Docker Daemon连接到Docker Registry，下载到Docker Daemon本机为images镜像。

  2. 要启动reids时，Docker Client 发送一个 docker run redis 的命令Docker Daemon，然后会先在本地找reids镜像images，如本地没有会去Docker Registry下载，然后再启动。

  3. 拿到镜像后，启动一个Docker Containers。

4. Docker 常见命令

  • 目标，启动一个nginx，将他的首页改成自己的页面，发布到市场，其他人可以下载

Docker 命令

  1. docker run

    • 用途：运行一个新的容器。
    • 示例：docker run -it ubuntu:latest bash
    • 示例：docker run -d 后台启动
    • 解释：运行一个基于最新 Ubuntu 镜像的交互式 Bash shell。

  2. docker ps

    • 用途：列出正在运行的容器。
    • 示例：docker ps
    • 解释：显示所有正在运行的容器。

  3. docker ps -a

    • 用途：列出所有容器（包括已停止的）。
    • 示例：docker ps -a
    • 解释：显示所有容器，无论它们的状态如何。

  4. docker stop

    • 用途：停止一个或多个正在运行的容器。
    • 示例：docker stop container_name_or_id
    • 解释：停止指定的容器。

  5. docker rm

    • 用途：移除一个或多个已停止的容器。
    • 示例：docker rm container_name_or_id
    • 解释：删除指定的容器。

  6. docker rmi

    • 用途：删除一个或多个镜像。
    • 示例：docker rmi image_name_or_id
    • 解释：删除指定的镜像。

  7. docker images

    • 用途：列出本地镜像仓库中的镜像。
    • 示例：docker images
    • 解释：显示本地镜像列表。

  8. docker pull

    • 用途：从 Docker Hub 或其他注册表拉取一个镜像。
    • 示例：docker pull nginx:latest
    • 解释：从 Docker Hub 拉取最新版本的 Nginx 镜像。

  9. docker push

    • 用途：将本地镜像推送到 Docker Hub 或其他注册表。
    • 示例：docker push your_username/myimage:tag
    • 解释：将本地镜像推送到 Docker Hub 的指定仓库。

  10. docker build

    • 用途：构建一个 Docker 镜像。
    • 示例：docker build -t myimage:tag .
    • 解释：构建一个名为 myimage 的镜像，并打上标签 tag。

  11. docker exec

    • 用途：在运行中的容器内执行命令。
    • 示例：docker exec -it container_name_or_id bash
    • 解释：在指定的容器内启动一个交互式的 Bash shell。

  12. docker logs

    • 用途：获取容器的日志输出。
    • 示例：docker logs container_name_or_id
    • 解释：显示指定容器的日志输出。

  13. docker network

    • 用途：管理 Docker 网络。
    • 示例：docker network create mynetwork
    • 解释：创建一个名为 mynetwork 的 Docker 网络。

  14. docker volume

    • 用途：管理 Docker 数据卷。
    • 示例：docker volume create myvolume
    • 解释：创建一个名为 myvolume 的 Docker 数据卷。

  15. docker-compose up

    • 用途：使用 Docker Compose 文件启动应用。
    • 示例：docker-compose up -d
    • 解释：使用 docker-compose.yml 文件中的配置启动应用，并以后台方式运行容器。

  16. docker-compose down

    • 用途：停止并移除由 Docker Compose 启动的应用。
    • 示例：docker-compose down
    • 解释：停止并移除所有由 docker-compose.yml 文件启动的容器。

  17. docker info

    • 用途：显示 Docker 系统的信息。
    • 示例：docker info
    • 解释：显示 Docker 系统的详细信息，包括版本、存储驱动等。

  18. docker search

    • 用途：搜索 Docker Hub 中的镜像。

    • 示例：docker search nginx

    • 解释：搜索 Docker Hub 中与 “nginx” 相关的镜像。

  19. docker stats
    • 用途：查询状态。

9. Docker 存储

  • 将docker中的目录挂载出来

目录挂载，将容器内的目录挂载到外面主机，当容器被删除时，其中的配置文件等不会丢失

  • 所以这个无法挂载配置文件，因为容器第一次启动时会会找不到配置文件

将容器中 /usr/share/nginx/html 映射到宿主机 /app/nginx/html 上，是以外面的目录为准，容器内的文件会不可见

  • 卷映射，可以将容器内部的文件映射出来，不会出现找不到配置文件
    • -v ngconf:/etc/nginx #前面是起一个卷名, 不以斜杠或点结尾
  • 然后会统一放在 /var/lib/docker/volumes/<volume-name>
