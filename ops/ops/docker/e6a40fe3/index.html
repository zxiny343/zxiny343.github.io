Docker简介

1. Docker 的产生背景

### 1.1 传统应用部署面临的问题

在 Docker 出现之前，企业级应用主要通过 物理机部署 或 虚拟机部署 的方式运行。随着业务复杂度和系统规模的扩大，这些传统部署模式逐渐暴露出一系列问题。

​ 1.1.1 环境不一致问题

实际开发流程中，通常会经历以下几个环境：

开发环境->测试环境->预发布环境->生产环境

不同环境之间在 操作系统版本、依赖库版本、运行时配置 等方面往往存在差异，导致经典问题：

“在我电脑上是好的，为什么上线就不行了？”

环境不一致会显著增加问题排查成本，并延缓交付效率。

​ 1.1.2 应用部署和迁移成本高

传统部署方式下:

  • 应用需要手动安装运行环境（如 JDK、Python、Node.js 等）
  • 依赖版本需要人工维护
  • 应用迁移到新服务器时，需要重复安装和配置

​ 1.1.3 资源利用率低

  • 物理机部署：资源固定，扩缩容困难

  • 虚拟机部署：

    • 每个虚拟机都包含完整操作系统
    • 启动慢（分钟级）
    • 占用磁盘和内存资源大

    在高并发和弹性需求场景下，传统虚拟化方式显得笨重且成本高昂。

随着互联网业务向 高并发、微服务、持续交付 演进，虚拟机逐渐成为效率瓶颈。

1.2 Docker 的诞生

​ 1.2.1 Docker 的目标非常明确：

让应用及其运行环境一次构建，到处运行（Build Once, Run Anywhere）

​ 1.2.2 Docker 的核心创新

Docker 并没有发明新的内核技术，而是对现有能力进行了系统化整合：

  • 标准化的镜像（Image）格式
  • 简单易用的 CLI
  • 声明式的 Dockerfile
  • 高效的镜像分层与复用机制

​ 1.2.3 Docker 出现带来的改变

开发：

  • 统一开发、测试、生产环境
  • 降低环境搭建成本
  • 提高本地调试效率

运维：

  • 标准化部署流程
  • 快速扩缩容（秒级）
  • 更易实现自动化和平台化

架构：

Docker 为以下技术和理念提供了基础支撑：

  • 微服务架构
  • DevOps
  • Kubernetes

1.3 Docker 与虚拟机的比较

​ 1.3.1 核心架构差异

虚拟机（VM）架构：

  • 基于 Hypervisor（如 VMware ESXi、KVM）
  • 每个虚拟机包含：
    • 完整操作系统
    • 独立内核
    • 应用及运行环境

Docker 容器架构：

  • 直接运行在宿主机操作系统之上共享宿主机内核
  • 每个容器仅包含：
    • 应用本身
    • 必要的运行时与依赖库

从架构上看，Docker 属于操作系统级虚拟化，而虚拟机属于硬件级虚拟化。

2. Docker安装

2.1 Docker 的运行环境要求

​ 2.1.1 操作系统要求

Docker 本质上依赖 Linux 内核能力，因此：

  • Linux：原生支持，生产环境首选，他依赖于已存在并运行的Linux内核环境。实质是在已经运行的Linux下制造了一个 隔离的文件环境，
  • Windows：几乎不会直接在 Windows Server 上运行 Docker 容器

Linux 内核版本 ≥ 3.10（CentOS 7 默认满足）

  • 发行版的通用标识文件,查询版本

2.2 Docker的基本组成

  • 镜像-image
  • 容器-container
  • 仓库-repository

2.3 Docker的工作原理

Docker 的核心工作机制可以概括为：

Docker 守护进程运行在主机上，通过 Socket 提供服务；Docker 客户端通过 Socket 与守护进程通信，将用户命令交由守护进程执行。

通过 Socket 通信特点：

  • 仅限本机访问
  • 性能高
  • 安全性相对可控

​ 2.3.1 Docker Client（客户端）

Docker Client 通常指的就是用户日常使用的 docker 命令。

其主要职责包括：

  • 接收用户输入的命令（如 docker run、docker ps）
  • 对命令参数进行基本解析
  • 将请求发送给 Docker Daemon

需要强调的是：

Docker Client 本身并不创建容器，也不直接操作镜像，它只是一个请求发起者。

​ 2.3.2 Docker Daemon（守护进程）

Docker Daemon（dockerd）是 Docker 架构中的核心组件，运行在宿主机后台。

其主要职责包括：

  • 接收来自 Docker Client 的请求
  • 管理镜像（拉取、存储、删除）
  • 创建、启动、停止和销毁容器
  • 管理网络、数据卷等 Docker 资源

可以认为：

所有真正“干活”的事情，都是 Docker Daemon 在做。

6. Docker 的基本工作流程

结合 Client / Server 架构，Docker 的工作流程可以概括为：

  1. 用户在客户端输入 docker 命令
  2. Docker Client 通过 Socket 发送请求
  3. Docker Daemon 接收并解析请求
  4. Docker Daemon 调用底层组件（containerd、runc）
  5. 容器在宿主机上以进程形式运行
