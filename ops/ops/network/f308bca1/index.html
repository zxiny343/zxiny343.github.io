网络传输安全的演变

一、 不安全的HTTP协议

HTTP（HyperText Transfer Protocol）本身是明文传输协议，在现代网络安全体系下被认定为“不安全协议”。下面从协议原理、攻击面、风险类型以及工程实践角度，系统性说明为什么 HTTP 不安全。

HTTP 工作在应用层（OSI 第七层），默认基于 TCP（通常端口 80）。

核心问题：

HTTP 不做任何加密、不做身份校验、不保证完整性。

1.1 HTTP 的三大安全缺陷

:one:无加密

HTTP 报文是纯文本：

攻击者只需：

  • 局域网抓包（Wireshark）
  • 公共 WiFi 嗅探
  • 路由器监听
  • 中间代理

即可直接看到：

  • 登录密码
  • Cookie
  • Token
  • 个人信息
  • 支付数据

这属于被动攻击（Sniffing）

2️⃣ 无完整性校验

攻击者可以：

  • 篡改返回页面
  • 注入恶意 JavaScript
  • 替换下载文件
  • 修改转账金额

典型场景：

浏览器不会察觉。

3️⃣ 无身份认证

HTTP 无法证明：

  • 你访问的服务器是否真实
  • 是否被 DNS 劫持
  • 是否被中间人代理

攻击场景：

DNS 劫持 → 指向攻击者服务器 → 伪造登录页面 → 获取密码

1.2 常见的攻击方式

:one: 中间人攻击

用户 ←→ 攻击者 ←→ 真实服务器

:two: 会话劫持

HTTP 下 Cookie 明文传输,攻击者复制后即可伪装成用户。

:three: 数据注入

在响应中注入js代码,以实现 钓鱼、XSS、恶意广告注入

:four: 重放攻击

攻击者抓取请求连接，然后重复发送

二、 技术演进方向

为了弥补 HTTP 的三大缺陷：

HTTP 问题 解决方案
明文 加密（对称/非对称）
无认证 证书体系（CA）
无完整性 摘要算法（Hash）

最终形成：

HTTPS = HTTP + SSL/TLS

也就是：

在 HTTP 下面加一层安全协议

  • 从协议演进角度看：

    1. HTTP —— 只解决通信问题
    2. 对称加密 —— 解决机密性
    3. 非对称加密 —— 解决密钥分发
    4. CA 证书 —— 解决身份认证
    5. TLS —— 整合所有能力

    这是安全体系的逐步升级。

:one: 引入对称加密

解决机密性问题

人们首先想到：

那就把数据加密再传输。

于是引入了对称加密算法。(DES、AES)

特点：

  • 加密和解密使用同一个密钥
  • 算法速度快
  • 适合大量数据传输

此解决了✅ 机密性 ，攻击者即使抓到数据，也无法直接看到明文。但又出现一个新问题：

  1. 密钥 K 怎么安全地从客户端传到服务器？

密钥在传输过程中，攻击者仍然可以截获密钥。

❗ 还是无法安全地“首次建立信任”。

于是进入下一阶段。

:two: 非对称加密

解决密钥分发问题

为了解决“密钥如何安全传输”的问题，引入：

非对称加密算法(RSA、ECC)

什么是非对称加密？

​ 特点：

  • 有一对密钥
    • 公钥（Public Key）
    • 私钥（Private Key）
  • 公钥加密
  • 私钥解密

流程：

客户端可以：

  • 用服务器公钥加密

  • 安全传输一个“对称密钥”

    这叫：

    混合加密模型（Hybrid Encryption）

实际流程：

  1. 客户端生成随机对称密钥
  2. 用服务器公钥加密这个密钥
  3. 发送给服务器
  4. 之后用对称加密通信

❗ 你怎么知道服务器的这个公钥是真的？（中间人攻击）

攻击步骤：攻击者可以

  1. 拦截连接
  2. 自己生成一对公私钥
  3. 把“假公钥”发给客户端

客户端加密后发送数据时实际发给了攻击者，攻击者解密后篡改后，在用服务器的公钥加密，转发给服务器。反之一样。

这就是：

中间人攻击（MITM）

非对称加密解决了密钥分发问题
但没有解决“身份认证问题”。

:three: CA 证书体系

解决身份认证

为了解决：

服务器公钥是否可信？

引入：

证书认证体系（PKI）

一些CA机构：DigiCert‌、Sectigo、GlobalSign‌、CFCA‌（中金金融认证中心）、Let’s Encrypt‌

CA做了什么：

  • 验证网站身份

  • 用自己的私钥给服务器公钥签名

  • 生成数字证书

    CA
 │
 │（签发）
 ▼

    服务器持有证书
    │
    │（TLS握手时发送）
    ▼
    客户端收到证书
    │
    │（验证签名）
    ▼
    使用证书里的公钥

浏览器内置：

  • 根证书列表

这基本解决了中间人攻击 MITM 问题。

:four: SSL / TLS 整合所有能力

最终，人们把：

  • 对称加密
  • 非对称加密
  • 数字签名
  • 证书体系

整合成一个完整协议：

  • SSL
  • TLS

现代使用的是 TLS。

能力 如何实现
机密性 对称加密
完整性 MAC / Hash
身份认证 数字证书
